The context window is how much of the conversation Qwen can see. 32768 suits agent mode; lower it if Ollama runs out of GPU memory. To go past 32K, use a long-context (YaRN) build from Models for this PC.


      
Ollama nodes

      
Run requests on more than one PC. Each node is an Ollama server reachable by URL (e.g. a second PC on your network); requests go to the first node that is online and has the model, and a task moves to the next node if one stops answering. "This PC" is the connection from the Model section. No node is used unless it is enabled here.

Planner (heavy model) handoff

      
Let your local Qwen do the grunt work and hand the hard parts to a stronger model. When it stalls, the next step runs on the planner automatically, and Qwen can also ask the planner for help with a consult_planner tool. The planner's answers are sent to that provider.

      
      

        
        
        
        
        
        
        

      


      
Remote sessions

      
See and drive this app's conversations from your other PCs (and theirs from here). Pair over your own network — e.g. Tailscale. The pairing code is a password: whoever has it can run this PC's agent with this PC's approval settings.

      
      

        
        
      

      

      
Paired devices (this PC as the viewer): add the other PC's URL, e.g. http://100.88.91.13:8931, and the pairing code it shows.

      

      

        
        
        
        
      

      


      
Escalation & costs

      
When the local model struggles, hand the step to the planner automatically — and see what cloud models cost. Both triggers are off by default; an Escalate button (✦, top-right of every reply) can also re-run any step on the planner by hand.

      
      
      
      
      
      
      
Model prices, per million tokens — empty by default. Copy current prices from your provider's pricing page; the app never guesses, and models without a price count as $0.

      

      

        
        

          
          
        

        
      

      


      
Semantic code index

      
Lets Qwen search this project by meaning ("where is auth handled?") with a semantic_search tool. Code is chunked at function/class boundaries; embeddings use Ollama's nomic-embed-text when it is installed (ollama pull nomic-embed-text), otherwise a built-in offline embedder. The index lives in .qwen/semindex.json and refreshes incrementally.

      

        
        
      


      
Automations

      
Recurring agent tasks. Each runs in the project folder it was created for, while the app is open with that folder; daily ones catch up on launch. Runs show in History with a ⏱ title. Needs Agent mode.

      

      

        
        
        

          
          
          
        

        
        
      


      
Skills

      
Task instructions Qwen loads on demand. Project skills live in .qwen/skills; Claude-format skills in the project's .claude/skills and your personal ~/.claude/skills are picked up too. Install one from GitHub by linking to a repo or to a folder that contains SKILL.md.

      

        
        
      

      

      


      
Tools & MCP servers

      
MCP servers add tools Qwen can use (e.g. reverse engineering, databases, browsers). Qwen loads a server's tools only when a task needs them, and each call needs your approval. Node-based servers need Node.js installed.
